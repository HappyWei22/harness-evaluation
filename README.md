# Harness 能力评测与失败分析

本项目评测 Codex、WorkBuddy、DeepSeek Harness（DSH）、豆包工作和元宝专家模式。Harness 是组织模型调用、工具执行、结果回传和任务状态的系统层。我们用可复核的场次记录，追踪任务在哪一步完成、失败或缺少证据。

## 受控运行与脱敏核验

- **Windows 受控启动。** 宿主机恢复登记的虚拟机检查点，准备本轮独立目录，检查登记的评分资料访问路径，再发出一次性许可。场次结束后按原生记录、产物和清理回执关账。已有正常放行和故意让模拟评分文件可读时拒绝投递的实机记录。 [受控启动方案与回执](docs/阶段进展/桌面端Agent受控启动方案与验收-2026-11-17.md) · [11 月 19 日「复制一行」实机证据](evidence/windows-single-task-2026-11-19/README.md)
- **macOS 诊断与模拟验收。** 公开七个模拟场景和一次真实诊断。诊断中原生文件工具可用，指定探针被拒读，命令工具执行受阻。 [脱敏核验包](evidence/controlled-startup-macos-2026-11-13/README.md)
- **历史评分核验。** 20 项 WorkBuddy 目录创建历史评分可离线复算。首轮办公试测有四项检查缺少原始依赖，已逐项封存并登记重开条件。 [评分材料与依赖核验](docs/阶段进展/Issue-3历史评分与依赖核验-2026-11-20.md) · [四种目录边界样例](evidence/workbuddy-mkdir/2026-11-05/README.md)

## 查材料与复核

- **评测设计。** 从单项行为出发，先写清题面、观察项和判据，再检查实际工具调用、结果与产物。 [评测方案](docs/评测方案.md) · [七维与权重](docs/七维能力与分值表.md) · [设计调整](docs/探索过程与方法调整.md) · [用例目录](cases/)
- **运行记录。** 使用独立工作区和新会话，保存题目版本、实际配置、运行时间与裁定。按产品运行、自测、离线复算等活动分别登记。 [十项记录模板](docs/评测方法/单次运行记录十项模板.md) · [活动分账](docs/评测方法/活动分类与分账说明.md) · [评分与证据规则](docs/打分与证据规则.md)
- **证据来源。** 公开包提供支撑判断的事件摘录、文件和来源说明。原件与公开副本的关系、脱敏和省略范围以各材料说明为准。 [现场导读](docs/表现现场导读.md) · [来源说明](docs/公开材料与来源说明.md) · [来源索引](PROVENANCE.json) · [文件指纹](MANIFEST.json) · [DSH 日志导出扩展](tools/dsh-context-export/README.md)

在仓库根目录用 Python 3.9 或更新版本运行以下命令，核对公开文件指纹、已有记录与评分之间的对应关系。

```bash
python3 -B checks/verify.py
```

加上 `--item WB-FB03-04` 可单独查看 WorkBuddy 在 FB03「截断后完整结果获取」中的全文保存准确性，同时检查全包指纹。命令只读取公开材料。核验通过表示材料和登记结论一致，其中也包括有证据支持的失败结果。 [复核说明](docs/复核说明.md) · [材料核对记录](checks/整理检查结果.md)
