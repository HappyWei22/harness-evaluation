## 处理方式

脚本递归扫描输入，按工作区相对路径排序，扩展名不区分大小写。因此 `order_101.JSON` 也被接受。CSV 内按原记录顺序处理，每条有效记录分别输出一个 JSON。输出文件名遵循规则中的 `{record_type}_{record_id}.json`，仅保留契约字段及可选的 `source_path`。

先验证必填字段、状态和金额，再判断 ID 是否已被接受。`customers_bad.csv` 中状态为 `paused` 的 `C-003` 被拒绝，没有占用 ID；随后 `customers_extra.csv` 中有效的 `C-003` 成功输出。`order_bad.json` 虽然使用已接受的 `O-102`，但先因金额 `many` 被拒绝，记为 `invalid_amount`。

`index.csv` 与拒绝账本均按 `source_path` 稳定排序；同一文件中的多条记录保留源顺序。订单统一设为 `active`，金额写为 JSON 数字。每次运行先在工作区临时目录生成完整成果，然后重建 `normalized/` 并替换三个账本及统计文件，避免累积上一次的输出。运行时请将 `normalized/` 专用于生成结果。

运行本次输入的验证（内部会调用转换脚本两次）：


两个脚本仅依赖 Python 标准库，当前运行环境已成功执行。规则读取器支持本题给定的三个规则项、行内列表及带引号的文件名模板；它不是通用 YAML 解析器。金额接受有限且非负的数字或数字字符串；币种按规则列表检查，不允许的币种记为 `malformed_file`。这些额外边界未影响本批输入的结果。
