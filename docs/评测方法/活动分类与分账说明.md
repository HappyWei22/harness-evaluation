> 公开副本：路径、会话标识和私人入口已脱敏；公开摘录不等于完整原件。来源SHA-256与原行号指向本地原件，公开文件字节指纹见MANIFEST.json；原字段内的指针不保证适用于变换后的公开副本。未公开原件不能由本包独立认证。


版本：1.0；日期：2026年10月30日。用于后续运行记录及本次WorkBuddy案例整理，历史记录暂不自动迁移。本说明落实导师要求的六类分账，分类依据是本次主要回答的问题，而非仅看使用了哪个工具或文件名。

## 六类活动

| 主要类型 | 本次主要回答什么问题 | 计入哪里、怎样使用 |
| --- | --- | --- |
| 产品运行 | 指定AI产品在实际配置下怎样执行任务或固定诊断步骤？ | 产品运行账；另写正式比较、探索、故障诊断等用途。符合比较条件的结果才进入对应比较 |
| 自测 | 评测方的材料、准备程序或检查流程本身是否正确？ | 评测端自测账，不计产品任务表现。例如检查输入是否齐全、脚本能否解析 |
| 离线复算 | 对已经保存的产物或轨迹，按指定规则重算会得到什么结果？ | 离线复算账，关联原运行ID及规则版本；新判定另存，保留旧判定，不新增产品运行 |
| 判卷回归 | 判卷器修改后，正例和近似错误例是否按预期判定，历史结果受到什么影响？ | 判卷回归账，关联修订前后代码及样例、验收、历史复算记录，不计产品成绩 |
| 裸模型探针 | 不经完整产品流程，模型在指定输入和配置下会怎样响应？ | 裸模型探针账，写模型接口、输入及所带工具，不能替代原生产品成绩 |
| 接口预检 | 正式任务前，入口、接口或参数是否可用，能否进入预期执行路径？ | 接口预检账，不拿连通或参数接受结果当正式任务成功；若实际开始任务，另留明确边界 |

## 三个字段分开填

每条记录填写“主要活动类型、研究用途、实际执行环境”。主要类型选一个，研究用途按实际描述，环境说明在哪里执行。例如，在产品中先检查接口能否用，主要类型仍可为接口预检；在产品中执行完整故障对照，则为产品运行、用途为故障诊断。

同一批工作包含产品运行、复算和判卷回归时，分别记录并用原运行ID关联。只读归档、摘录日志、补填设置属于对原记录的整理，注明整理日期和来源，不冒充新产品运行。一次评分修订同时涉及回归与历史复算时，可分别保存关联子记录，但不得把同一次重算执行重复计数。

原生配置、人工指定脚本、模型自主规划是不同事实，应在操作部分说明。产品能够执行评测者给定脚本，不等于产品自主设计实验、诊断或修复；名称含“探针”也不意味着属于裸模型探针。

## 计数方法

- 产品任务尝试、工具调用、脚本内预定观察分别计数；一次工具调用中的三个观察不自动成为三次独立产品运行。
- 人工中断后续做、同一输出的转存和归档，不据此自动新增产品任务尝试；按原任务边界记录。
- 已提交但未进入工具执行的尝试单列，保留提交次数、执行状态和原因，不直接计为已执行任务失败。
- 场景未成立、材料被污染等有效性问题，与任务业务成败分别记录。缺证据保留未知；预设错误正确出现不等于对照失败。
- 六类统计分别汇总，不混成产品成功率；未知、未测不按已评部分折算满分。
