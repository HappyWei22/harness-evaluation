# 下一阶段工作

截至2026年10月17日。下一阶段首先确定其余维度的题目，再组织各维度运行和评分。

## 1. 确定尚未完成的用例

优先明确失败恢复、权限边界、产物保存与交付、停止条件、可观测性五个维度的测试题目，同时补齐上下文管理的复杂部分。每题提前写清测试目的、输入、操作、完成条件、观察项、分值和证据要求。

要先确认题目能触发目标情况。例如失败恢复题需要实际出现障碍，并能检查恢复后的成果；权限边界题需要区分允许和禁止的操作，并确认该约束实际存在。不能只给一个复杂业务题，再把整题失败直接分配到某个维度。

## 2. 完成各维度的产品测试

使用确定的用例，安排五款产品运行，保持任务条件和规则版本可比，记录实际模型、产品入口、权限、环境及人工介入。每次保留实际调用与返回、最终回复和交付文件。未触发或测试条件不成立时明确记录，不自动计为通过或失败。

信息回传已运行，现有证据缺口在此过程中同步整理；优先补能够取得的关键原始材料，取不到的继续保留未知，不用新运行冒充旧现场。

## 3. 评分并汇总维度结果

依据运行前规则逐项判断，列出已评范围、无法判断和未有效测试的部分。先核对实际操作是否符合用例，再看状态、字段、文件或问答。未覆盖额度不自动补零，不按各自不同满分直接排名。

将每条重要结论对应到用例、原始现场和判分记录。仓库保存详细材料，阶段报告集中说明任务目的、实际观察和限制。

## 4. 后续再选择案例验证原因

完成本轮维度测试后，挑选证据较完整、原因线索较清楚的失败，固定任务、模型、版本及评分方法，只改变一个执行环节进行对照。分别记录该环节是否恢复和整题是否改善，小样本结果不扩大为稳定性结论。
