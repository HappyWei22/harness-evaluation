# 桌面端 Agent 受控启动方案与 Windows 验收进展

截至 2026 年 11 月 17 日。Windows 11 上的 DeepSeek Harness（DSH）已实测正常放行和模拟评分资料可读时的拦截。双请求并发已通过 Windows 自测，实际连接 DSH 的并发验收待做。

## 为什么要在发送前检查

上一次「三文件修订与多轮交付」的页脚实验有四轮在约 62 秒内陆续启动，运行发生重叠，读取隔离也缺少验证。四轮结果保留为探索记录。导师在 Issue #2 要求把串行、独立工作区和评分资料读取检查设成发送正式题目前的强制条件，并故意制造并发与资料可读两种情况，验证正式入口确实会拦截。 [页脚实验](../../results/art04-footer-authorization-2026-11-06/README.md) · [导师反馈](https://github.com/HappyWei22/harness-evaluation/issues/2)

前期在 macOS 上做过 DSH 命令行接入。真实诊断能调用文件工具，但命令执行工具应用自身限制时遇到了外层沙箱兼容问题。于是先在 Windows 上验证另一条路线：由宿主机管理运行，桌面产品在独立虚拟机里使用自己的工具。 [第 5 周周报](../周报/第5周周报.md)

## 一轮任务如何受控启动

1. **先取得运行锁，再核对上一轮。** 同一受管环境只有一个请求能持有启动锁。宿主机同时用 SQLite 持久化运行状态。启动程序退出后锁可能释放，因此接手的请求还要查有没有提交不明、未确认结束或者未清理的旧任务。有任何一项未解决，就拦截新请求。
2. **从已登记的初态准备本轮。** Windows 实测用 Hyper-V 检查点恢复虚拟机，检查实际启动记录，再为本轮建立独立目录与会话。核对输入清单、文件指纹和空输出目录，检查旧产物和未登记的路径映射。同步、历史引用和远端连接器要按产品实际配置另查。正式题面和真实评分资料由宿主机保管。
3. **按产品实际使用的通道检查读权限。** 先登记共享目录、网络服务和相关远端工具。用授权文件确认原生读取工具能正常工作，用评分侧生成的无敏感随机标记检查相关通道。诊断有自己的许可，只能投递探针题面。工具返回与宿主机原件一致，就能确认该文件确实可读。若通道未开放，需要文件存在性、配置和实际访问结果共同支持。路径错误、工具失败或证据缺失会让该项保持未知，正式许可暂停发放。
4. **条件满足后才释放正式题面。** 归档并清理诊断，为正式任务建立新会话，重新确认输入、当前启动实例和相关配置。一次性许可在宿主机登记，实际发送前先把「正在提交」写入数据库。发送超时或回执丢失时，查客户端会话或任务记录确认是否收到，期间禁止自动重发。会话、环境或权限发生关键变化时，旧许可失效。
5. **以结束和清理证据关闭本轮。** 查原生终止事件，归档指定产物和轨迹，恢复初态并检查本轮残留，再关闭运行记录。能脱离本地继续执行的云端任务，还须查对应的远端终态。状态仍未知时按既定时限停止核查并保持阻塞。业务是否成功、运行是否有效、观察项能否纳入比较分别裁定。

这里的「启动前」指正式题面进入产品之前。读取诊断会产生自己的真实会话。是否需要重新执行诊断取决于证据能否覆盖本轮实际使用的身份、配置和读取通道，尤其要核对恢复基线或配置变化后的现场。方案的强制范围是被接入的投递入口，手工投递等其他入口需另行管控和验收。

## Windows 已完成的验收

### G01 正常启动

- **观察。** DSH 接收一条正式验收消息，从新工作区读回授权样本并正常结束。
- **证据。** 原生轨迹有一条操作员消息、一次成功的 `read` 调用和一个正常终止事件。工具返回与宿主机原件逐字节比对。宿主机收尾回执记录归档已匹配，恢复后本轮目录、启动器和会话均无残留。 [脱敏回执](../../evidence/controlled-startup-windows-2026-11-17/g01-normal-start.json)
- **解释。** 这次实测跑通了准备、正式提交、结束和清理。前置诊断结合网络配置，只支持当时所登记的宿主机共享通道未暴露。
- **未排除因素。** 结论限于这一套 Windows 与 DSH 桌面配置和这条通道。其他读取通道与其他产品待核对，本轮尚无独立验收。
- **可复现实验。** 恢复登记基线，检查授权读取和评分侧访问边界。用新工作区提交一次冻结的短题面，从原生轨迹核对唯一提交、读取和终态，再核对归档与恢复后的残留。上述步骤均已在本轮执行。

### G08 模拟评分资料可读

- **观察。** DSH 在诊断中读到了工作区外故意放置的模拟评分文件。随后的正式请求被拒绝，正式尝试、许可和提交各新增 0 次。
- **证据。** 原生轨迹中的两次读取分别对应授权样本和模拟文件，两份返回均与宿主机留存原件的指纹一致。宿主机正式入口报告拒绝原因为 `simulated_grading_material_readable`。收尾回传显示诊断已关闭，归档保留，虚拟机中的模拟文件及本轮目录已清理。 [脱敏回执](../../evidence/controlled-startup-windows-2026-11-17/g08-readable-grading-material.json)
- **解释。** 正式入口确认评分侧模拟材料可读后，在签发许可前拦截了请求。真正在 DSH 运行的是独立的读取诊断。
- **未排除因素。** 本次反例使用虚拟机内的本地文件通道。其他共享、连接器和产品范围仍需验证。本轮尚无独立验收。
- **可复现实验。** 把无敏感随机标记放在产品能访问的隔离测试区。用授权样本和标记分别做一次原生读取，比对两份返回，再从正式入口请求投递并核对拒绝原因和三项计数。保留诊断证据并检查恢复后的残留。上述步骤均已在本轮执行。

公开回执保留事件序号、调用与返回关系、比对结果和宿主机记录的关键字段。原始归档及身份、完整路径、会话标识、随机文本保留在本地。本页两项结论使用 E2 过程证据。G01 和 G08 使用验收替代题面，业务能力评分和跨产品比较另行开展。 [证据等级说明](../评测方法/证据等级说明.md)
