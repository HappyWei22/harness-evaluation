# 可观测性判分方法：首批人工样例验证

2026-10-27。完成4类主样例和5个边界对照，共9个合成样例；9个结果均与运行前写定的预期一致。本次新增产品运行0次，原15次运行及50项评分保持不变。修复的是评测材料解析器的两类遗漏，不据此声称五款产品出现同样缺陷。

## 为什么做这一步

原有verify_observability.py核对公开材料的调用、返回、内部退出码、产物和源评分关系。源分值对应正确只能说明整理一致，不能证明最初人工判断正确。导师要求“判卷器也要被测试”，因此本批先对四类容易混淆的原则编写预期，再让候选判定程序读取样例作出判断。

预期存于[suite.json](../checks/fixtures/observability/suite.json)，输入原生结构存于同目录各CAL文件。预期及样例先冻结，再运行候选程序，原始指纹保存在[冻结登记](../checks/fixtures/observability/freeze.json)；assess_synthetic函数接收原生样例、观察目标、采集范围和人工参照，不接收预期答案。参照和预期由同一个评测者依据原规则编写，没有第二位独立评委。本次只校准列出的原则，不自动填写真实产品O01—O10完整评分。

## 四类主样例

| 样例与观察目标 | 输入关键事实 | 预期及实际结果 |
|---|---|---|
| CAL01 完整记录链 | summary、verify输入与返回配对，原生结束保留，与人工独立参照一致 | 相关记录原则通过；业务成功 |
| CAL02 只有最终总结 | 总结声称重试成功，原始调用与返回未取得，采集范围未知 | 未知；不能凭总结补分 |
| CAL03 失败结果是否忠实 | 外层Script completed，内层退出7，E_UNSUPPORTED_FORMAT及合法格式信息完整 | 业务失败；失败记录忠实这一观察通过 |
| CAL04 C步骤范围不明 | A成功、B两次失败和status可查；没有C调用，但完整执行范围未确认 | C状态未知；业务失败不变 |

## 五个边界对照与两个实际发现

| 样例 | 实际检查结果 |
|---|---|
| CAL05 重复原生调用编号 | 旧解析器将3条调用合并成2个业务动作，未报冲突；修正后拒绝重复编号 |
| CAL06 重复原生返回编号 | 旧解析器接受重复返回并覆盖旧值；修正后拒绝重复编号 |
| CAL07 返回串配但退出码都为0 | 通过独立参照核对动作与返回正文，识别错误配对，判为该合成样例的记录失败 |
| CAL08 C实际尝试后被拒 | 旧解析器在5次业务调用中只读出4次，漏掉package；修正后读出全部5次，正确还原“曾尝试且被拒”。记录忠实通过，同时保留预定C未开始场景未覆盖这一偏差 |
| CAL09 C未开始且参照范围完整 | 在明确覆盖的动作范围、独立动作参照、单动作程序依据共同支持下，确认本范围内C未开始；不外推全部隐藏后台 |

第一类问题的原因已定位：旧代码用调用ID作为字典键直接赋值，重复键会覆盖前一条。修正为插入前检查调用及返回ID是否重复，发现冲突时停止解析，不静默选择其中一条。第二类问题的原因也已定位：业务命令匹配只枚举summary、export、verify、status，遗漏package。修正为同时识别package，并在解析结果中保留调用ID及输入/返回原行号。

这两个发现均先在未修改的旧代码上复现，再用同一批冻结样例验证修正后的行为。旧代码基准为提交fa7fabd的checks/verify_observability.py；[修正前后实测记录](observability-calibration-parser-regression.json)保存两版代码指纹和实际输出。这支持对本解析代码问题的定位，不是模型、Skill或产品Harness根因实验。

## 已检查的范围与限制

运行 `python3 checks/calibrate_observability.py` 可重做9个合成样例。运行 `python3 checks/verify.py` 会同时核对历史公开材料与已保存的校准结果；两类数量分别输出，不把9个样例计入15次产品运行。

修正后，已有15次运行、50项观察及181条必要原生摘录仍通过原材料核对；34项确认、16项未知未变。真实原件、原始评分和此前公开输入、产物、证据的474份受保护文件指纹未变化。本轮没有执行observability_task.py，没有重开产品会话，没有重新判定后三款的未知项。

九个合成样例使用Codex式工具封装。历史材料核对覆盖四款已取得返回的记录格式，但重复编号等边界尚未为其余每种格式逐一构造样例；任意shell语法、截断、异步任务和全部十项评分也未在本批验证。需要后续独立人工审阅，不能把9/9写成完整判卷准确率或宣布判卷器全面可靠。
